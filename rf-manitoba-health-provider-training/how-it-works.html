How the Q&A pipeline works

Learners' questions become private GitHub Issues. Presenters answer them there. Once an editor approves one, GitHub Actions turns it into a Markdown file in the course and rebuilds the site. Every step leaves a record in Git.

Automatic steps run by themselves. Person steps need someone to act. Nothing is published without a person approving it.

The steps

  1. A learner asks a question

    Automatic

    The form checks for identifying details while they type (email, phone, PHIN or SIN, postal code, dates, names after "Mr." or "my client"). It asks the learner to remove them before sending. Try it on the sample page.

  2. A small relay creates a private Issue

    Automatic

    Learners don't have GitHub accounts, so the form sends to a small serverless function (on Netlify or Cloudflare). It checks for spam, runs the privacy check again, keeps the learner's email out of the Issue, and opens an Issue with labels for the section and which presenter it's for.

  3. The right presenter is notified

    Automatic

    A label such as for: lived experience assigns the Issue. GitHub emails the presenter, and they can answer by replying to that email. The reply becomes a comment on the Issue.

  4. An editor reviews and approves

    Person

    The editor checks accuracy and removes any identifying details the automatic check missed. They can reword the question for general use, then add the approved label.

  5. GitHub Actions writes the Q&A file

    Automatic

    The approved label starts a workflow. It runs a stronger privacy scan on the question and the answer, writes a Markdown file, and opens a pull request. The editor can see exactly what will be published.

  6. Merge, build and publish

    Person Automatic

    Merging the pull request rebuilds the site. The Q&A appears under "Questions from other providers" in its section, and the Issue closes. If the learner left an email, they get a note saying it's answered.

  7. Answers are kept up to date

    Automatic

    Benefit rules change. A scheduled workflow opens a review Issue for any answer that hasn't been reviewed in 12 months.

About the privacy check

The automatic checks catch structured details such as numbers, emails, postal codes and dates. They're weaker on names, places and rare conditions, which can identify someone when combined. The workflow can add a stronger scan (a named-entity tool such as Microsoft Presidio, or an AI review) that flags anything doubtful. Even so, the editor's approval is the real safeguard, and nothing skips it.

Still to decide

  • Where the relay function runs (Netlify or Cloudflare). GitHub Pages alone can't receive form submissions.
  • Whether presenters get their own GitHub accounts, or an editor passes questions to them.
  • Who the editors are, and how quickly questions should be answered.
  • How long questions and learner emails are kept.
